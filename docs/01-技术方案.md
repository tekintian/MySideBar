# MySideBar 技术方案

> 版本：v1.0（方案阶段）
> 适用：Sublime Text 4（Python 3.8）
> 状态：待评审

---

## 1. 项目背景

整合 `_res/` 下三个 Sublime Text 插件的功能，形成全新的侧边栏增强插件 `MySideBar`。

| 源插件 | 许可 | 处理方式 |
|---|---|---|
| SideBarEnhancements | GPL v3 | **不复制代码，按思路重写**，避免 GPL 传染 |
| SideBarMenuAdvanced | MIT | 仅借鉴“遮蔽原生菜单”的思路，内联实现 |
| sublime-gbk-support | 未声明、来源不明 | **完全重写**，不复制代码 |
| send2trash（来自 SideBarEnhancements） | BSD | 保留（含版权头），三平台实现 |

### 1.1 目标

- 提供完整、可靠的侧边栏文件操作能力，面向中文开发者使用习惯。
- 补齐 Sublime Text 原生短板：批量正则改名、GBK 编码、回收站删除、视图联动。
- 全代码重写，无外部依赖，无 GPL 传染。

### 1.2 非目标

- 不重写 Sublime Text 的文件内容搜索/替换（使用原生 `find_in_files`）。
- 不实现 VS Code 风格的侧边栏文件名过滤框（ST 侧边栏 UI 不支持注入）。
- 不实现 ST2/ST3 兼容层。
- 不提供在线更新、捐赠、推广入口。

## 2. 需求清单（最终版）

### 2.1 保留功能

| 分类 | 功能 | 说明 |
|---|---|---|
| 新建 | 新建文件 / 新建文件夹 | 中文/英文输入框，自动创建父目录 |
| 打开 | 编辑 / 在右侧编辑 / 用系统程序打开 / 在当前终端打开 / 在新窗口打开 / 在文件管理器中定位 | 三平台实现 |
| 查找 | 在选中项中查找 / 文件名递归搜索 | 后者为原 Instant File Search 重写 |
| 剪贴板 | 剪切 / 复制 / 粘贴 / 复制名称 / 复制相对路径 / 复制绝对路径 | 侧边栏私有剪贴板与系统剪贴板双写 |
| 文件操作 | 重命名 / 复制副本 / 移动 / 删除 | 删除走回收站，失败兜底永久删除 |
| **批量改名** | **批量正则改名（含目录/递归/预览/撤销）** | **本次核心新增** |
| 编码 | GBK / GB18030 / UTF-8 打开、另存、转换 | 全新实现，不使用临时 .dump 文件 |
| 项目 | 加入项目 / 从项目移除 | 原名 Promote / Unpromote |
| 菜单 | 遮蔽 ST 原生侧边栏菜单项 | 通过菜单文件 + 空壳命令 |

### 2.2 移除功能（不做）

| 移除项 | 原因 |
|---|---|
| Data URI 复制 | 大文件占满剪贴板且阻塞 UI；现代构建工具已覆盖 |
| 状态栏文件大小 | 非刚需，引入 `hurry.filesize` 依赖与裸 `except` |
| tag a / tag script / tag style | 目标路径基准不可靠、模板过时、场景低频 |
| `Mass Rename` | 字面量替换、无预览、无冲突检测、静默失败，不符合使用习惯 |
| 多行编辑框改名 | 与“1 个批量改名命令”的决策冲突，已取消 |
| 捐赠 / 哨兵命令（aaaaa、zzzzz） | 与功能无关的 hack |
| `Edit.py` 兼容层 | ST4 不需要 |
| `.dump` 临时文件方案 | 脏实现，改用原生编码 API |

### 2.3 批量改名需求（详细）

| 编号 | 规则 | 说明 |
|---|---|---|
| R1 | **只能修改相对路径下的子路径，绝对不可修改父路径** | 基准根永不参与改名；目标路径必须落在基准根内 |
| R2 | **改名对象是相对路径** | 而非仅文件名 |
| R3 | **可选项：是否包含目录** | 默认关闭；关闭时目录不参与改名 |
| R4 | **包含目录时，先改目录（深度逆序），再改文件** | 保证 source 有效、target 处于终态 |
| R5 | 默认模式为**正则** | 支持 `$1` 与 `\1` 反向引用 |
| R6 | 单一入口 | 侧边栏右键仅一个「批量改名…」，无多行编辑框 |
| R7 | 提供**撤销上一次批量改名** | 基于回滚日志 |
| R8 | 必须提供**预览与冲突校验** | 未通过校验的项拒绝执行 |

## 4. 国际化方案

### 4.1 事实依据

Sublime Text **不提供界面语言 API**，原生界面始终为英文。参考 `_res/ChineseLocalization`（第三方 ST 语言包）的实际实现，其语言判定仅依赖 `locale.getdefaultlocale()` 且只在首次安装时生效，之后完全由用户手动切换。

因此本项目采用更克制的策略：

- **插件默认英文**。
- **不做任何区域自动探测**（不使用 `locale`、`LANG`、`LC_ALL`、Windows 注册表）。
- **仅首次安装时询问一次语言**，之后固定使用用户选择，不再重复询问。

### 4.2 语言策略

设置项 `ui_language` 取值：`"en"`（默认）| `"zh_CN"` | `"zh_TW"`。

| 时机 | 行为 |
|---|---|---|
| 首次安装（`first_run == true`） | 弹出一次性语言选择面板：`English` / `简体中文` / `繁體中文` |
| 用户完成选择 | 写入 `ui_language`，置 `first_run = false`，永久不再询问 |
| 用户取消选择（Esc / 关闭面板） | 视为选择 `en`，置 `first_run = false`，**不重复弹出** |
| 后续启动 | 仅读取 `ui_language`，不探测、不询问 |
| 手动切换 | 主菜单 `Preferences → MySideBar → Language` 中选择，写入设置并应用菜单覆盖 |

**实现约束**：
- 首次选择面板在 `plugin_loaded` 中以 `sublime.set_timeout(..., 200)` 延后触发。
- 触发前校验存在有效 `window`（`sublime.windows()` 至少一个）；无窗口时（如命令行批量调用）跳过询问，保留 `first_run == true` 供下次交互启动时再问。
- 关闭面板/无选择回调时同样置 `first_run = false`。

### 4.3 文案实现

| 资源 | 英文（默认） | 中文 |
|---|---|---|
| 运行期提示（状态栏、对话框） | `i18n.t(key)` 返回英文 | 同 key 返回中文 |
| 菜单（`.sublime-menu`） | 包内英文菜单 | 中文菜单模板 |
| 命令面板（`Commands.sublime-commands`） | 英文 | 中文 |

**菜单切换机制**：

- 包内始终提供**英文菜单**（默认生效）。
- 当 `ui_language` 为中文时，`plugin_loaded` 将中文菜单模板写入 `Packages/User/MySideBar/` 下的**同名菜单文件**，ST 以 User 资源覆盖包内资源。
- 为避免每次启动重复写入，使用标记文件 `Packages/User/MySideBar/.applied_lang`，内容为当前已应用语言；与 `ui_language` 一致则跳过写入。
- 语言切换后需要 `sublime_plugin.reload_plugin` 或提示用户重启 ST 使菜单生效。
- **降级策略**：若覆盖未生效，侧边栏右键菜单保持英文，运行期提示仍按 `ui_language` 显示。

**参考实现对照**：`_res/ChineseLocalization` 采用“解压中文菜单覆盖 `Packages/Default/`”的方式接管全系统菜单，并附带多重 `patch` 目录与黑名单以规避冲突。本插件**不触碰 `Default` 包**，只覆盖自身包内菜单，从机制上避免与任何第三方语言包冲突。

**验证项 V1**：确认 `Packages/User/MySideBar/` 下的菜单文件能覆盖包内同名菜单（机制已由第三方实践证实，此处仅确认作用域与生效时机）。

### 4.4 文案规范

- key 命名：`模块.动作.状态`，如 `file_ops.rename.conflict`。
- 英文文案首字母大写、无句号。
- 中文文案使用全角标点。
- 所有硬编码英文/中文**禁止**出现在业务代码中，必须经 `i18n.t()`。

## 5. 核心模块设计

### 5.1 api.py（重写 SideBarAPI）

| 类 | 职责 |
|---|---|
| `SideBarSelection` | 解析右键选中的 `paths`，提供 `files` / `dirs` / `items` / `without_child_items`；缓存按窗口+路径计算 |
| `SideBarProject` | `folders()`、`project_data()`、加入/移除目录、刷新 |
| `SideBarItem` | 路径操作：`join`、`dirname`、`exists`、`create`、`copy`、`move`、`retarget_views`、`reveal` |

关键修正（相对原插件）：

1. 删除 `aaaaa/zzzzz` 哨兵与 `Cache.cached` 全局缓存，改为**按调用实时计算**（选中项规模小，性能可接受）。
2. `_itemsWithoutContainingChildItems` 使用 `os.path.commonpath` 判断，而非字符串前缀，避免 `a` 与 `ab` 误判。
3. `retarget_views` 统一使用 `os.path.normcase` 判断，覆盖 Windows 大小写与路径分隔符差异。
4. 所有 `try/except: pass` 改为**捕获具体异常并上报**，不允许静默吞错。

### 5.2 batch/patterns.py

```python
def apply(rel_old: str, options: RenameOptions) -> str
```

- `pattern_type == "regex"`：
  - `$n` / `${n}` 先转换为 Python 的 `\g<n>` 语法。
  - `re.sub` 作用于 `rel_old` 或 `stem`（按 `scope`）。
  - 替换后若残留 `$\d` 视为引用越界 → 抛 `PatternError`。
- `pattern_type == "sequence"`：
  - 输出 `prefix + str(start + idx).zfill(digits) + suffix`。
- 抛出 `PatternError`（中文/英文由 `i18n` 决定），命令层捕获并回到输入面板。

### 5.3 batch/plan.py

```python
@dataclass
class RenameOptions: ...
@dataclass
class PlanItem: ...
class RenamePlan:
    base: str
    items: List[PlanItem]
    stats: dict

def collect(selected_paths, options) -> Tuple[str, List[Path]]
def compute(base, paths, options) -> RenamePlan
def validate(plan) -> RenamePlan
```

**collect**：
1. 计算 `base` = 选中项最深公共父；若选中项是目录则 `base` = 该目录。`base` 本身**绝不进入计划**（R1）。
2. 是否递归由 `recursive` 决定；是否收集目录由 `include_dirs` 决定。
3. 跳过 symlink（计数 `skipped_link`）。

**compute**（纯内存）：
1. `rel_old = relpath(path, base)`
2. `rel_new = patterns.apply(rel_old, options)`
3. `new_abs = normpath(join(base, rel_new))`

**validate**（就地更新 `status`）：

| 条件 | status |
|---|---|
| `rel_new` 为空 | `invalid` |
| `rel_new` 以 `..` 开头或为绝对路径 | `invalid`（违反 R1） |
| `new_abs` 不在 `base` 内（`commonpath`） | `invalid` |
| leaf 含非法字符或超长 | `invalid` |
| 只读目标 | `invalid` |
| 同批 `new_abs`（normcase）重复 | `conflict` |
| 磁盘已存在且不属本批将移走的项 | `conflict` |
| `rel_old == rel_new` | `skipped` |
| 环 / 大小写变化 | `needs_temp = True`，status `ok` |

### 5.4 batch/execute.py

**执行顺序（唯一自洽实现）**：

```
Step 0  中间名：needs_temp 项 rename 到 base/.mysidebar_tmp/{uuid}
Step 1  目录批：kind == "dir"，按 depth 逆序
        src = join(dirname(cur_actual), old_leaf)
        dst = join(dirname(cur_actual), new_leaf)
        os.rename(src, dst)          # 目录整树搬移，子项自动跟随
Step 2  文件批：kind == "file"
        parent_final = final_parent_of(old_abs)    # 由阶段1的目录映射查得
        src = join(parent_final, old_leaf)
        dst = join(parent_final, new_leaf)
Step 3  中间名项落地到终态
Step 4  按映射表 M 一次性 retarget 所有视图
Step 5  写回滚日志
```

**正确性论证**：

- 目录批逆序：子目录先改名，父目录后改名；父目录 rename 时整树搬移，子项自动到达终态，无需跨父搬运。
- 文件批在目录批之后：所有目录已处于终态，文件实际位置 = `final_parent + old_leaf`，source 一定有效、target 一定处于终态。
- 只有**一次**映射表 M（由 compute 生成），执行期不做任何前缀 remap，从机制上消除“同名重复被修改”的隐患。

**失败处理**：任一步抛异常 → 停止 → 按已执行项**逆序回滚** → 上报错误。

### 5.5 batch/rollback.py

- 日志路径：`Packages/User/MySideBar/rename_log.json`（不污染项目目录）。
- 结构：`{"timestamp": ..., "base": ..., "ops": [{"old": ..., "new": ..., "kind": ...}]}`
- 撤销：**逆序**执行 `os.rename(new, old)`；执行前校验 `new` 存在、`old` 不存在。
- 撤销后执行 retarget（`new → old`）。
- 只保留最近一次。

### 5.6 ui/preview.py

- 渲染为 scratch 视图，语法 `MySideBar Rename Preview`。
- 头部：基准目录、统计、模式、选项。
- 逐行：`[ok ] / [!  ] / [!! ] / [=  ] / [~  ]` + `相对路径（旧） → 相对路径（新）` + 括号内原因。
- 只显示**相对路径**，不显示绝对路径（防止用户误以为可修改父级）。
- 执行方式：整批（默认）或「只执行选中行」（选区内行号映射到 PlanItem 索引）。

### 5.7 cmds/batch_rename.py

```python
class MySidebarBatchRenameCommand(sublime_plugin.WindowCommand):
    def run(self, paths=[], pattern_type="regex")
    def is_visible(self, paths=[])
    def is_enabled(self, paths=[])

class MySidebarBatchRenameApplyCommand(sublime_plugin.TextCommand):
    def run(self, edit, whole=True)

class MySidebarBatchRenameUndoCommand(sublime_plugin.WindowCommand):
    def run(self)
    def is_enabled(self)
```

- `is_visible`：选中项 ≥ 1；不含 mount point；不含项目根；无选中项时不可见。
- 输入流程：正则 → 替换（若 `pattern_type == "regex"`）/ 前缀、位数、后缀（若 `sequence`）→ 选项（包含目录、递归、仅文件名）→ 预览。

### 5.8 cmds/encoding.py

- 打开：使用 `sublime.load_file_with_encoding` 或读取字节后 `view.set_encoding("GBK")` + `view.run_command("reopen")`。
- 转换：读取源编码文本 → `view.set_encoding(target)` → 保存。
- 丢弃 `.dump` 方案。
- 转换失败必须给出明确错误（非法字节、超大文件）。

### 5.9 cmds/shadow.py

- 空壳 `WindowCommand` 覆盖 ST 原生侧边栏命令：`new_file_at`、`delete_file`、`new_folder`、`delete_folder`、`rename_path`、`open_containing_folder`、`find_in_folder`。
- 实现为 `is_visible() -> False`、`is_enabled() -> False`，**不 import `Default.side_bar`**（原 SideBarMenuAdvanced 做法在跨平台下会崩）。
- 遮蔽依据是**命令名**，与菜单语言无关：第三方语言包只会翻译 caption，命令名不变，因此遮蔽对任何语言包同样有效（见风险 V6）。

## 6. 数据流：批量改名

```
右键「批量改名…」
   → 收集 paths
   → InputPanel：正则
   → InputPanel：替换
   → QuickPanel：选项（包含目录 / 递归 / 仅文件名）
   → collect()         枚举基准根与参与项
   → compute()         生成映射表 M
   → validate()        冲突 / 非法 / 跳过 标记
   → preview()         渲染预览视图（可选中部分行）
   → [确认] execute()  Step0~Step5
   → rollback log      写日志
   → retarget views
   → 结果提示（成功/跳过/失败计数）
```

## 7. 错误与边界清单（实现必须逐项闭环）

### 7.1 批量改名

| # | 场景 | 处理 |
|---|---|---|
| 1 | 正则非法 | 编译期捕获，报错并回到输入面板 |
| 2 | 正则为空 | 拒绝 |
| 3 | `$n` 引用越界 | 替换后残留检查，判非法 |
| 4 | 目录名指向父路径外 | invalid，拒绝 |
| 5 | 同批重名 | conflict，跳过该项 |
| 6 | 磁盘已有同名 | conflict |
| 7 | 换名 / 大小写变化 | 中间名 |
| 8 | 文件被打开且未保存 | 执行前 `is_dirty` 提示 |
| 9 | 只读文件 | `W_OK` 检查，invalid |
| 10 | 超长路径 | 逐项检查，invalid |
| 11 | 递归遇 symlink | 跳过并计数 |

## 9. 复盘校验结论

### 9.1 第一轮复盘（需求遗漏 / 边界）

| 检查 | 结论 |
|---|---|
| 语言默认值 | 已修正为“默认英文，仅首次安装询问一次语言，之后固定，不做区域探测” |
| ST 界面语言 API | 经核实不存在；参考第三方语言包实现（依赖 `locale`，仅首次生效），本插件改为首次询问，彻底移除探测代码 |
| 批量改名执行顺序 | 已确认为“目录逆序 → 文件”，并给出正确性论证 |
| 撤销的视图联动 | 补入撤销后 retarget |
| 日志位置 | 移出项目目录，放 `Packages/User/MySideBar/` |
| 编码模块 | 明确丢弃 `.dump` 方案 |
| 首次询问的边界 | 补入“取消视为 en 且不重复询问”“无窗口时跳过”两条边界 |

### 9.2 第二轮复盘（架构 / 权限 / 迭代成本）

| 维度 | 结论 |
|---|---|
| 架构 | 菜单 → 命令 → 领域 → 平台四层；`batch/` 与 `api.py` 无 ST UI 依赖，可独立验证 |
| 权限 | 全部操作限制在基准根内；`is_visible` 拦截项目根与 mount point |
| 数据库 | 无 |
| 前端 | 1 个预览语法 + 1 个 scratch 预览视图 + InputPanel；无多行编辑视图 |
| 兼容性 | ST4 only，声明 `"version": "4.0"` |
| 迭代成本 | 低：新增改名模式只需增加 `patterns.apply` 分支；新增校验只需增加一条规则 |
| 技术债 | 删除原 `Mass Rename`、多行编辑方案、`.dump`、`Edit.py`、`hurry`、哨兵命令；执行引擎只保留一套 |

## 10. 风险与待验证项

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| V1 | `Packages/User/MySideBar/` 下菜单覆盖包内同名菜单的生效时机与作用域 | 中文菜单不生效或需重启 | 机制已被第三方实践证实，仅需真机确认；未生效则退化为仅运行期文案中文 |
